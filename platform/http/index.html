The platform · HTTP

Other servers, bodies as they came, and cookies

The server answers HTTP, and asks too: an API's JSON, a sign-in provider's token, a linked page. This page covers requests to other servers, request bodies, raw and forwarded answers, and cookies.

Every sample here is from server/test/app/Samples.roc, compiled and run by the server platform's tests.

Asking another server#

Http.fetch!(url, init) works like JavaScript's fetch: it sends a request and waits for the whole answer, holding no thread meanwhile (how calls pause). init is an Http.Init record. Every field has a default, so {} is a plain GET:

  • method: Get, Post, Put, Patch, Delete, Head, Options, or Other("PROPFIND") for any other, sent as written.
  • headers: (name, value) pairs, sent as given.
  • query: pairs, percent-encoded and added to the URL's query (after an & if it has one).
  • body: Empty (the default), or Http.json(value), Http.form(pairs), Http.plain_text(text) or Http.bytes(list). Each sets content-type unless headers has one; bytes set none, like fetch with a Uint8Array.
  • timeout_ms, max_bytes and redirect: the limits, below.
  • proxy: FromEnv, Direct or Via(url), below.

A record literal works wherever an Http.Init is expected. To keep one and build on it, annotate it (as authed above) and update it: { ..authed, method: Delete }.

Any status is an answer: Ok holds an HttpResponse with res.status, res.ok (true for a 2xx), res.headers, res.header(name) (any case), res.text(), res.json() (decoded as the type you ask for, or InvalidJson(why)) and res.bytes(). Err means no answer at all.

An older API (Http.get, post_form, post_json, with_header, send!(request, opts), send_request!, Http.header, Http.text) is deprecated; each is fetch! underneath. The storage package takes Http.send! because it names no platform, so it can't name Http.Init.

Limits and errors#

By default a request may take 30 seconds (timeout_ms), its body up to 64 MiB (max_bytes), and redirects are followed (redirect: Follow). For a URL a stranger gave you, ask for less, as above. 0 means no limit; Manual returns a redirect as the answer. The errors:

  • HttpErr(why): no answer. The address was unreachable, the connection or TLS failed, the server broke HTTP, or a header had a line break.
  • TimedOut: no whole answer in time, counted from connecting to the body's last byte.
  • TooLarge: the body was over the limit, by its content-length or as it arrived.

Redirects are followed like a browser's fetch, 20 at most. A 303 (or a 301 or 302 answering a POST) becomes a GET without its body; authorization and cookie headers aren't sent to another origin. TLS is rustls, checked against the web's certificate authorities. Nothing is decompressed: if you send accept-encoding, you get the body as the server sent it.

Connections and proxies#

Connections are kept alive and reused by the next request to the same place (scheme, host, port and proxy), so an API you call often costs one TCP and TLS handshake, not one per request. An idle connection is kept 30 seconds, or a second less than its server says (keep-alive: timeout=5); at most 32 idle per place, any number open. If the server closed a kept connection meanwhile, the request is retried once on a new one, if it was never sent or is safe to send twice (GET, HEAD, OPTIONS, TRACE, PUT, DELETE, or with an idempotency-key header), as Go's client does.

  • The environment's proxy (FromEnv, the default), read as Go reads it: HTTPS_PROXY for https URLs, HTTP_PROXY for http. Never for localhost, a loopback address, or a host NO_PROXY names. NO_PROXY takes *, an address, a range (10.0.0.0/8), example.com (that name and every name under it) or .example.com (only names under it), each with an optional :port.
  • A request's own proxy: Direct uses none; Via(url) uses that proxy for every host. A proxy URL is http:// or https://; a user and password in it go as proxy-authorization. An unreadable proxy URL is an HttpErr, never a silent way around the proxy.
  • Through the proxy, an http request goes to the proxy whole. An https one goes through a CONNECT tunnel with TLS to the server inside, so the proxy sees none of it.

Reading an answer as it arrives#

Http.fetch_chunks!(url, init, start, step!) makes the same request as fetch! but never holds the whole answer. It calls step! with Head(res) first (status and headers, empty body), then Chunk(bytes) for each part of the body as it arrives. Like a fold, each call gets the previous return value, starting from start; the value after the last chunk is the result. If step! returns an Err, the request stops and its connection closes (Err(Stopped(why))).

Use it for a body too large to hold, or one to pass on as it comes, like a language model's answer sent word by word to a stream of events. timeout_ms runs to the last byte and max_bytes counts every chunk, so set both to 0 for a long stream.

Request bodies are bytes#

A request's body is a List(U8), never decoded on the way: an upload is exactly what the client sent. Server.text_of(request) reads it as UTF-8 (U+FFFD where invalid). Server.bytes(status, headers, bytes) answers with raw bytes.

An endpoint decodes its input from the body only when it is JSON (application/json, or a type ending in +json) or a form (URL-encoded, or multipart/form-data, whose files come as their names). For any other type (an image, a video), give the handler the input type {} and read request.body yourself; a handler that expects fields answers such a body 415. A multipart form's files are Server.files(request), or one by field with Server.file(request, field), each with its name, type and bytes.

A route file may name the rules its body is checked with (post_body = Signup.form, from packages/forms). Form fields and a JSON object are then read alike, and what the rules refuse never reaches the handler: it gets 422, with the issues as JSON (endpoints).

A request's body is read whole before your code runs, 16 MiB at most unless the server's --max-body (MAX_BODY) allows more (running it).

Passing on a body from elsewhere#

Server.forward(upstream, headers) is an answer whose body never passes through Roc. The host asks upstream and streams the answer on, so a 500 MB video costs your code nothing and starts playing at once. The answer takes upstream's status (200, 206 for a range, 304, 404) and its body's headers (content-type, content-length, content-range, accept-ranges, etag, last-modified); headers you give are added or replace those.

  • Only what your code says goes upstream. The host adds nothing from the request, so its cookies stay here. Server.passed_on(request) gives the request's Range, If-Range, If-None-Match and If-Modified-Since headers to pass on. Change the request record first (drop a range that doesn't fit, say) to change what is asked.
  • An error upstream (400 or more) is answered with its status and standard reason as text, never upstream's body, which might name a bucket. No answer is a 502 (a 504 after 30 s), logged without the URL's query, where a presigned URL keeps its signature. A body cut short closes the client's connection, so it never passes as complete.
  • The storage package's Storage.serve! is a forward to S3 for an S3 bucket (storage); for a directory or memory, the server sends the file it keeps (Server.stored).

Cookies#

Server.set_cookie(answer, name, value, options) adds a Set-Cookie header. Server.CookieOpts holds its attributes. Server.cookie_defaults, changed with a record update, are: path /, http_only, same_site: Lax, this host only, until the browser closes. When the app's public URL is HTTPS, the server marks every cookie it sets Secure, so leaving secure off only matters over plain HTTP in development.

  • max_age_s (Max-Age) and expires_ms (Expires, in milliseconds since the epoch) are left out when 0. With neither, the cookie ends when the browser closes.
  • secure, http_only, same_site (Lax, Strict or None), path and domain are each left out when empty. Browsers drop a __Host- cookie unless it is secure with path / and no domain, and drop SameSite=None without secure.
  • Server.clear_cookie takes the path, domain and secure the cookie was set with. Server.with_cookie and Server.without_cookie set and clear one with the defaults. The value is %XX-encoded; Server.cookie(request, name) decodes it.

.well-known, and every method#

A .well-known directory is routed like any other, so what other servers look for there (an OAuth server's metadata, security.txt) is an ordinary route file. Other directories starting with a dot aren't routed.

A +server.roc usually defines one function per method (get!, post!, put!…). respond! answers every method the file doesn't name: given the request, the path's params and the context, it returns its own Server.Response. Use it for a protocol that speaks POST and GET at one URL, or a page a package draws (the jobs page). It isn't an endpoint, so it stays out of /openapi.json (endpoints).

Not yet#

  • HTTP/1.1 only, each way: no HTTP/2, and no SOCKS proxy.
  • A request's body is whole in Roc, in or out: no streaming. (Another server's answer can be read in chunks, and a forwarded body never enters Roc.)

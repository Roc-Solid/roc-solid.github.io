Examples · examples/echo

echo

The smallest app on the server platform: two endpoints and nothing around them (no +middleware.roc). POST /echo answers with the JSON string it was sent; POST /echo/json reads a nested order into a typed record and writes it back. No browser half: it measures the server itself, and what reading and writing JSON adds.

SourceREADMEAll the examples

What it shows#

  • Everything a request goes through, and nothing more
  • A body read into a nested typed record, and written back
  • The server's benchmark, on each endpoint

The benchmark#

Its server, built with --opt=speed as it would ship, under bombardier, which sends a request on each of its connections, the next as soon as the answer is in, for 10 seconds at each number of connections, after a warm-up: first to POST /echo, then to POST /echo/json (examples/echo/bench.sh runs the same). Every request goes through the host, the generated routes, a middleware that only passes it on, reading the JSON body and writing the JSON answer. What differs is the body: a string, then an order that nests.

echo (simple)

Each request is POST /echo with content-type: application/json and the body "hello" (7 bytes): a JSON string, which the endpoint reads into a Str and answers as it is. It's the least an endpoint can be asked, so what's left is the server's own cost.

echo (json)

Each request is POST /echo/json with an order: a customer with an address, items each with its tags, shipping and a note, 725 bytes as sent (compact, as a client sends JSON). The endpoint reads it into a record of its type, Shop.Order (records in records, a list of records, lists of strings, numbers and a Bool), and answers with it, written as JSON again: what most endpoints do with a body. One the type doesn't fit is refused with a 400 before the endpoint runs.

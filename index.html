What Roc Solid is#

Roc Solid is a web framework for Roc, a functional language that compiles to native code and to WebAssembly. You write components in .rocx files: Roc with HTML-like markup. The counter below is one. Step through how it gets from its file to your screen.

An app gets:

  • Pages from files. routes/blog/[slug]/+page.rocx is the page at /blog/…, inside its folders' layouts. Every route has a typed link.
  • Signals, as in SolidJS. A component runs once. When a signal changes, only the markup that reads it runs again.
  • Typed endpoints. A +server.roc answers HTTP. A page reads one as a plain value while the server renders it, and the answer ships inside the page.
  • Forms and live updates: actions with optimistic updates, channels and server-sent events.
  • One native server executable, with Postgres or SQLite, migrations, a key-value store and actors.
  • Packages for jobs and cron, email, charts, forms, Markdown, an admin and more.
  • Errors at your lines. The compiler checks every value you put in a page, and reports each mistake at its line in your .rocx file.

Getting started#

  1. 1

    Install

    One command installs rocx, its Roc compiler and both platforms, prebuilt, into ~/.rocx (macOS on Apple silicon, Linux on arm64 or x86_64). No Rust, Zig or Node needed. It verifies each download and adds ~/.rocx/bin to your PATH. With Nix: nix profile install github:Roc-Solid/rocx.

    The first release isn't out yet. Until then, build from a clone with git and just: just setup fetches the rest into .tools/ and builds bin/rocx.

  2. 2

    Make an app

    rocx new makes an app in its own folder and asks which database: SQLite (the default, a file beside the server), Postgres or Turso. It comes with sign-in by a mailed link (or Google and GitHub, once their keys are set), optional two-factor codes, a users table, refusal of other sites' posts, and rate-limited sign-in mail.

    rocx dev serves it at http://localhost:8080. Each save rebuilds it, restarts the server and reloads your open pages; a mistake shows at its line, and the last good build keeps running. Under rocx dev, sign in with any address, no mail needed. The app's README.md says what to change first, and how to test (rocx test), deploy (rocx build or rocx build --image) and upgrade (rocx upgrade).

  3. 3

    Add a page, or an endpoint

    Each file in routes/ answers the URL its folders spell; that folder is all an app needs. A +page.rocx is a page: rendered to HTML on the server, made live in the browser. A +server.roc is an endpoint: functions named after HTTP methods (get!, post!) that answer with JSON.

    view! runs once: it makes a signal and returns markup. The button's text reads the count, so it updates when the count does. get! answers GET /hello with a JSON string.

Next: rocx covers pages, components and routes; syntax lists everything markup can hold; tooling covers every command; the platform is what the server and the browser give an app; and the examples are complete apps to read.

Three parts#

rocx

What you write: Roc with markup wherever an expression can go. rocx build turns each page, layout and component into plain Roc with the same line numbers, for the compiler to check.

rocx →

Platform

What an app runs on. On the server: native Roc in a Rust host, with Postgres or SQLite, a key-value store, live channels, actors, and plugins that let packages add routes and jobs. In the browser: the same components in WebAssembly, and a small JavaScript runtime.

The platform →

Ecosystem

Packages of plain Roc and components, for both halves of an app. Twenty-four so far: sign-in, Stripe payments, Claude, charts, crypto, file storage (S3, disk or memory), email, forms, Markdown, intl, an admin, audio, guards, jobs and cron, MCP, tools for models, OpenTelemetry, PostHog, presence, Web Push, QR codes, vibration, testing and virtual lists.

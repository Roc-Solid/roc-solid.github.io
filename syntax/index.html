Syntax

Markup wherever an expression can stand

A .rocx file is Roc with markup (HTML elements and components) wherever an expression can stand; inside markup, braces take you back to Roc. rocx build turns markup into calls to the platform's Html module, so every .rocx file has import pf.Html. Each example is a real file in site/examples, shown with its output; its switch shows the Roc rocx wrote.

Elements, text and fragments#

Elements are written as in HTML, tag names in lower case. Empty elements close themselves (<br />, <img />, <input />); a bare <br> is refused. Text is escaped: a < in a name shows as itself, never as a tag.

Markup is an ordinary Roc expression: name it, return it, put it in a list. A fragment, <>…</>, holds elements side by side, so nothing needs a single root; <></> is nothing at all. The Roc rocx writes keeps your line numbers, so compiler reports point at your lines.

Holes: Roc values in markup#

A hole, {x}, puts a Roc expression in markup, shown by its type: a Str as escaped text, a number as digits, Html as markup. Any other type, such as a Bool or a record, is a compile error at your line. A list hole, {...xs}, shows a List(Html)'s items in order.

In a component, a hole reruns and patches its own node when what it reads changes: a call of a name ending in ! (a signal such as count!(), a memo, an accessor prop) or an effectful component's prop. Any other hole is worked out once.

One kind of hole

rocx runs before the compiler, so it can't know x's type. It writes Html.hole(x) (inside Html.hole_of(|| …) when it reads what changes, Html.shown(x) when not), and the compiler picks how to show the value from its type, through Roc's encoding. {=x}, in older code, is the same hole.

Terms

rocx refuses an unquoted value (class=big), a whole computed style (style={…}) and an inline handler (onclick="…"; in a component, write on:click={…}). A style: value is dropped if it holds anything but letters, digits, spaces and .,%#()-+, or calls a CSS function that could load something (rgb(), calc(), var() and other computing functions are fine; url() is not). URL attributes (href, src, action and a few more) take only safe URLs.

Why style takes no values

A whole style from data lets data decide layout and load URLs. Instead, switch classes, pass a number through a custom property, or set one property named in the file, style:color={…}, whose value is checked: for where no stylesheet reaches, such as an email's colours (email clients read neither stylesheets nor custom properties).

In a component, where values change, they keep the markup they made:

  • An if or match on something changing keeps its branch's markup, and the signals of components inside, while that branch holds; it makes another branch's markup only when that one holds. A match arm's names always read the newest value.
  • A .map over a changing list makes rows kept by key, given on each row's outermost element or component: {...todos!().map(|todo| <li key={todo.id}>{todo.title}</li>)}. A row is made once per key, moved on a reorder and dropped when its key goes, so focus and typing inside survive. It updates only when its item is no longer == the old one. A row that is an if keys each branch.
  • .map_with_index(|item, i| <li key={i}>…</li>) makes a row per position instead: rows stay put, each showing the item now at its position.
  • rocx refuses a changing list without a key, at its line, saying what to write, and a key that mixes the index with something else (write key={i} alone).

Components#

A capitalised tag is a component: a function from a record of props to Html. <StatusPill status={s} /> calls StatusPill.view (or view!) when the file imports or defines a StatusPill module, and this file's status_pill otherwise. Each attribute is a prop: a string, a Roc value in braces, or a bare name (Bool.True). What is between the tags is the children prop, a List(Html). A missing prop is a type error, unless the props are a nominal record with defaults (title : Str ?? "").

There are two kinds of component (pure and effectful):

  • A pure component, view with no !, is a plain function, called where it is written. Its props are values; it makes no signals.
  • An effectful component, view!, runs once, where it is rendered, and may make signals. Its value props are getters: rocx passes each as a function, so reading the prop gets the current value, and a parent can pass something that changes.
WrittenMeans
<Field value!={draft!} />A prop named with ! is an accessor, called like a signal: value!() (props that change).
<Card {...rest} />Passes a record of props on as is, such as the rest of a view's props (|{ title, ..rest }|).
<Repeat count!={n!()}>{|index| …}</Repeat>A function as the only child is passed as children to the component's view_with!, which calls it.
<ThemeContext value={dark}>…</ThemeContext>Provides a context, defined with create_context, to the markup inside (contexts).
<Card key={card.id} … />On a component that is a list row's outermost tag, key is the row's key, never a prop.

Handlers, keys and transitions#

A handler, on:event={…}, is a Roc function the browser runs when the event reaches the element. It may set signals, call the server and so on; the server renders nothing for it. A suffix on the event's name says what the handler is given, or when it runs:

WrittenMeans
on:click={|| …}Runs on the event. on:submit also stops the browser's own submit.
on:input.value={set_draft!}Given the element's value, a Str.
on:change.checked={|on| …}Given whether it is checked, a Bool.
on:keydown.key={|key| …}Given the key's name (Enter, k). .keys gives the key and the modifier keys held (keys.shift, keys.mod…).
on:keydown.Escape={|| …}Runs for that key alone, with no modifier held, and stops the browser's default (an arrow key scrolling the page). .Space is the space bar; letters and digits work too (.w).
on:keydown.Mod+K={|| …}Runs for that key with exactly those modifier keys held: Shift, Ctrl, Alt, Meta, and Mod, which is ⌘ on macOS and Ctrl elsewhere.
on:click.prevent={|| …}Stops the browser's default first, such as following a link the page takes over.
on:pointermove.point={|p| …}Given where the pointer is over the element, as shares of its width and height.
on:drop.data={|items| …}, .filesGiven what a drop or a paste carries, or its files; on:change.files on a file input gives the files chosen.
on:frame.ms={|ms| …}Runs every animation frame while the element is on the page, given the milliseconds since the last.
on:viewport={|view| …}Runs when the element shows, and each time it scrolls or changes size, given what of it shows.

Other attributes that only mean something in the browser:

  • key={…} names an element: on a list row, its key; anywhere, it keeps an element moved between lists the same element, so it can glide between them.
  • transition={…}, transition:in={…} and transition:out={…} play an animation (a Transition, such as Transition.fade) as the element's row or branch comes and goes; transition:move={…} glides it when it moves (transitions).
  • drag:data={[(type, value)]} is what a drag of the element carries, and drag:image={id} the element shown while it is dragged (drag and drop).

Markup inside a <NoHydration> never runs in the browser, so rocx refuses a handler, key, transition or drag: attribute there, at its line. The components page covers signals and handlers in depth.

Built-in tags#

A few capitalised tags are rocx's own, unless your file has a module of the same name:

WrittenMeans
<NoHydration>…</NoHydration>Markup only the server renders. The browser keeps its HTML as is; none of the code inside is in the wasm.
<Document on:keydown.Mod+K={…} />, <Window on:resize={…} />Handlers on the whole document or window, while the markup around the tag is rendered. They take only handlers and render nothing.
<Meta name="description" content={…} />, <Link … />, <Style>…</Style>A <meta>, <link> or <style> in the document's <head>, while the markup around the tag is rendered.
<!doctype html>The doctype, at the top of a root layout.
<story name="…">…</story>One way a component looks, for the dev build's catalog (stories).

The platform also has components you import (import pf.Loading, and so on): <Loading fallback={…}> and <Errored fallback={…}> for waiting and failing, <Repeat> for rows without a list, <Title> for the document's title, and <Navigate> for navigating.

Whitespace, as HTML has it#

Text follows HTML's rule, as in Svelte (not JSX): each run of spaces, tabs and line breaks is one space. Whitespace with a line break next to an element's own opening or closing tag is dropped; a space on the tag's line stays (<b>On the tag's line: </b>). So prose can break lines anywhere, even next to a link or a value, and elements on lines of their own get a space between them. <pre> and <textarea> keep text as written.

Comments, entities, script and style#

{# … } and <!-- … --> are comments; they never reach the page. A {# … } comment ends at the first }, so it can't contain one. Entities work: the common named ones (&amp;, &middot;, &nbsp;…) and numeric ones (&#x2192;); rocx refuses one it doesn't know. Write a literal <, >, { or } in text as an entity or a string in a hole ({"{"}), so a stray brace is never silently text.

A <script> or <style> in markup keeps its text as written, braces included, and takes no holes: a page's script is part of the page, never data. A <style> beside a component's definitions, outside its markup, is scoped to that component.

Styles, scoped to their component#

A <style> in a component's block, beside its definitions, styles only that component's markup, as in Svelte. rocx adds a class named after the component to each element written in the block and to each selector: .card .title becomes .card.rx-… .title:where(.rx-…), one class more specific than written, however long the selector. So two components' .card rules never meet, even in one file; a bare p is only this component's paragraphs; and styles don't reach into the components it renders. A page or layout has no block, so its <style> goes at the file's top level, for the whole file. A component, or a file's top level, has at most one <style>, with no attributes. Its lines are blank in the Roc, so line numbers stay yours.

Reach outside the component as in Svelte: :global(body), div :global(strong) for any strong inside this component's divs, and a :global { … } block for rules that are all global. A component's @keyframes spin, and spin in its animation, are its own; @keyframes -global-spin is everyone's spin. Nested rules work, & too.

rocx build puts every <style> in the app into one stylesheet, Generated/Styles.roc. The root layout adds it to its <head> with {Styles.style}: a <link> to /rocx/styles-hash.css, named by its content, so the browser keeps it for every page and any change gives it a new name.

Stories#

A <story name="…"> in a component's block holds the markup of one way the component looks; its name starts with a letter, and the tag takes nothing else. Each story becomes a definition in its place (<story name="Tip"> is story_tip!), so every build checks it against the component, but only a dev build (rocx dev) shows it, in a catalog at /__rocx/stories (stories).

Where < starts markup#

< starts markup only where an expression can begin, and only when a letter, > or ! follows. After a value on the same line it is a comparison.

WrittenRead as
x = <b>hi</b>, f(<b/>), [<i/>, <b/>], Html ?? <></>markup: after =, (, [, ,, ??
|post| <li>…</li>, A => <b/>markup: a lambda's body, a branch
if (a < b) <b/> else <i/>a comparison in the condition, then markup after it and after else
first on its linemarkup: a block's last expression
a < b, f(x)<y, n<ba comparison: a value comes before it
"<b>", '<', # <i>left alone: strings, characters and comments

Types#

Markup is the platform's Html type everywhere. A pure component, view, is a function such as { … } -> Html; an effectful one, view!, an effect: { … } => Html. A prop's default may be markup: fallback : Html ?? <></>. In plain Roc, these build markup without rocx:

FunctionFor
Html.to_strHtml -> Strmarkup with nothing to run in it, as a string: an email's HTML, an expect
Html.textStr -> Htmlescaped text
Html.joinList(Html) -> Htmlseveral, as one
Html.empty{} -> Htmlnothing at all (<></> in markup)

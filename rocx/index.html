rocx · Roc Solid's markup

Write pages and components in Roc. Render them on the server. Run them in the browser.

A .rocx file is Roc with markup wherever an expression can go; pages, layouts and components are all written this way. rocx build turns it into plain Roc, line for line, for the Roc compiler to check. The server renders a page to HTML, and the browser runs the same Roc, compiled to WebAssembly, to keep it live.

Learn the syntaxComponents

Why rocx#

Checked by Roc

Every {hole} is a Roc expression the compiler checks: a hole shows text, a number or markup; a list hole takes a List(Html), an attribute a Str, a handler a function of the right type. Errors point at your .rocx line, quoting your code.

Safe by construction

Html is opaque: no string can become markup. Text and attribute values are escaped, URLs that could run script are replaced, and handlers are Roc functions, never script in an attribute (safety).

Line for line

Line N of the generated Roc is line N of your file, so compiler reports, dbg and crash messages point to the right place, with no source maps to break.

Fine-grained, end to end

As in SolidJS, a component runs once. A change reruns only the holes that read it, each patching its own node; nothing is re-rendered to find what changed.

Pages, components, endpoints#

Pages

A page is a file, routes/…/+page.rocx, at the URL its folders spell. It is a component the server renders for each request, inside the layouts above it, and the browser hydrates. What it wraps in <NoHydration> stays the server's HTML.

Routing →

Components

SolidJS 2.0's model: a component runs once and may make signals, values that change, and the holes that read them rerun. A page places a component like an element.

Components →

Endpoints

A route's +server.roc holds its endpoints: a function per HTTP method at a URL, typed at both ends. A component reads a GET as a plain value; the server answers it while rendering, and the page carries the answer to the browser. The handler runs only on the server and isn't in the browser's download.

rocx build writes Counter.roc beside it. Its lines 9 to 20, the same lines as above, with the markup turned into calls to the platform's Html module:

  • What calls a ! function, such as count!(), can change, so it becomes a function the browser reruns: {count!().to_str()} is Html.hole_of(|| …), and class:negative={…} is Html.class_of("negative", || …). What can't change is written once: an attribute from the file is Html.attr_literal, text is Html.text.
  • A handler, on:click={…}, is a Roc function given to Html.on.
  • An effectful component's (view!) props become getters: start_value is a function, read where the code reads it, so a parent can pass a changing value.
  • The class rx-49lxy6 comes from the component's <style>, which rocx scopes to its markup and moves into the app's stylesheet.

A route file's Roc goes into the app's Generated/ folder instead. The syntax page covers everything you can write in markup, tooling the commands, and safety what rocx refuses to build, and why.

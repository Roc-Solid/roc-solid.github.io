A game and a flock, run by Roc

Ordinary components, rendered by the server and hydrated in your browser, that also run on time. Each animation frame calls a Roc handler that moves things. Only the holes that read what moved run again, patching the few attributes that changed.

A flock of Roc birds#

The line under each demo is measured live: a frame's time covers the handler that moves and collides the birds, the holes that read the flock, and their patches.

How they work#

Time is a handler

on:frame.ms={|ms| send!(Frame(ms))} runs its handler every animation frame, given the milliseconds since the last, while its element is on the page. The snake's sits inside an if that holds only while you play, so a paused game, like an empty sky, runs no frames.

Keys that do one thing

on:keydown.ArrowUp={|| send!(Turn(Up))} runs for that key only and stops it scrolling the page. Other keys, Tab among them, work as usual.

Rows that stay, so little changes

The birds are .map rows keyed by id, so each keeps its element; a move sets two custom properties the stylesheet turns into a translation. The snake's segments are rows by position (.map_with_index(|part, i| … key={i})): each step, a segment takes the cell ahead, and a one-step CSS transition slides it there.

Pure, so it replays

The rules are a plain function, update: last game and your move in, next game out, kept in a signal. Roc has no hidden randomness: the food's next place and a new bird's heading come from a seed in the game (Demos/Random.roc). The same moves give the same game, and every rule is an expect away from a test.

What isn't shown isn't read

The snake moves a cell per step's worth of frames. The time since its last move is a signal nothing reads, so a frame that only adds to it runs no hole and patches nothing.

Sound, from a handler#

update is pure, so it can't make a sound. The next game names its step's sound instead ("eat", "die", or nothing), which a test can check, and the handler that sets the game plays it with Audio.play!, from the audio plugin package (its script in the page plays it):

It plays any file the browser can (WAV, MP3, Ogg, from anywhere), with nothing prepared: the browser fetches each file once and keeps it. These are chiptune notes of a few KB, made by site/sounds.mjs. The flock plays one pop at every pitch with Audio.play_with!(url, { volume, rate }): each new bird plays it a little faster, a higher note.

A sound plays once the handler is done and the page is patched. Only handlers play sounds; in a hole or on the server, it fails. For browser features with no platform module (the clipboard, say), a handler calls the page's JavaScript with Browser.call!(name, arg), like Elm's ports. Nothing comes back; for answers, ask the server (talking to the server).

The stopwatch keeps its interval's clear! in a signal, and Stop calls it:

On each key, the search clears the last timeout and starts its own, so it searches once, 400 ms after the last key. The clock clears nothing: a timer belongs to what started it (a component, or the part of the page a handler's element is in) and stops when that goes. Hide the clock and its ticks stop. Solid needs onCleanup(() => clearInterval(id)) for this; here it is built in.

The server starts none

No timer runs on the server: the clock renders at 0, and the browser starts its interval as it hydrates.

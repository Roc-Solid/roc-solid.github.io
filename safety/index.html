Safety

Data can't become markup

Cross-site scripting is data (a name, a comment, a URL) landing in a page as markup or script. In rocx a value is always text, so a page's only markup is what its .rocx files contain: there is no escaping to remember.

Html is opaque#

Markup is the platform's Html type; outside its module, no string can become markup. Every value goes through one of these doors:

Text and attributes

Escaped: < > & " ' come out as entities, in text and in attribute values.

URLs

href, src, action, formaction, poster and cite take only safe URLs.

Styles

A style:color or style:--size value is dropped if it could end the declaration or calls a function that loads something (url(…)).

Tags and script

Tags, attribute names and the text of <script> and <style> come only from the file, never from a value.

Names in hand-written Roc#

Plain Roc can build markup with Html.element, Html.void and Html.attr (and Html.optional, Html.flag and their computed forms), where a tag or attribute name is a Str that could come from data. Text and values are escaped as in a file, and every renderer (the server's, the browser's, Html.to_str) leaves out a name that isn't plain:

  • A tag is an ASCII letter, then letters, digits and - (p, h2, linearGradient, acme-card). img src=x onerror=… isn't, so that element and its contents are left out.
  • An attribute is an ASCII letter, then letters, digits, -, _, . and : (data-id, aria-label, xml:lang, viewBox), never starting with on: an inline handler (onclick) runs script, while Roc's is on:click (below). The element is written without a bad one.
  • A <script> is written only as a .rocx file has it, with its text as written there (Html.source_text, which rocx lint refuses in hand-written Roc). One built from text, a hole, or only a src is left out.

A bad name never fails a page; it is left out, and reported. The server logs rocx server: markup named what a page can't have, which wasn't written with the page's path and the names, once per render; the browser warns on the console, once per name. .rocx files are unaffected: their names come from the file, and the build refuses inline handlers there.

Try to break it#

This component renders <a href={url} title={text}>{text}</a> with whatever you type, twice: as Html.to_str writes it, as the server would (compiled to WebAssembly here), and live, where the runtime sets holes as text and attributes, never markup.

<a href={url} title={text}>{text}</a> renders as

<a href="about:invalid#rocx-unsafe-url" title="&lt;script&gt;alert(1)&lt;/script&gt;">&lt;script&gt;alert(1)&lt;/script&gt;</a>

and here it is, live:

<script>alert(1)</script>

URLs#

A URL attribute takes a relative URL or an http, https, mailto or tel one; anything else becomes about:invalid#rocx-unsafe-url. Tabs, line breaks and leading spaces in a scheme are dropped first, since browsers ignore them (java\tscript: runs). In a picture's URL (<img src>, <link href>, <source src>, <video poster>), data:image/… passes too, SVG included: a picture runs no script.

The check runs in the platform's Html module, in Roc, whenever a value becomes an attribute, so the server's markup and the browser's patches agree. What this page rendered for these values in an href:

Handlers aren't script#

onclick="…" is refused: it is script in an attribute. A component's on:click={…} is a Roc function, which the server renders nothing for and the browser never sees as text. The runtime builds elements with createElement and sets text and attributes directly, never parsing markup, so a value can't become a tag. A handler inside a <NoHydration>, which is never hydrated, is refused at its line.

What the server sends the browser is data too

The page's endpoint answers travel at its end as JSON, in a <script type="application/json">, every < written as \u003c so no answer can end the script. The runtime parses them; nothing runs them.

Requests from other sites#

Another site's page can make a visitor's browser send your app a request with its cookies (a form that posts, a script that fetches). So the platform answers 403 to a POST, PUT, PATCH or DELETE to an endpoint whose Origin isn't your server. Clients that aren't pages (curl, another server) send no Origin and are answered; a GET changes nothing and is answered whoever asks.

The check runs on every request, before the app's middleware, unless App.program says cross_site: Allowed (an API other sites' pages call, with CORS); then Middleware.same_origin({}) in a directory's +middleware.roc puts it back where needed. Cookies from Server.with_cookie are HttpOnly (no script reads them) and SameSite=Lax (another site's form doesn't send them).

rocx lint#

Html.source_text is how rocx writes a <script>'s or <style>'s text from the file. In hand-written Roc it would put any string in a page as markup, so rocx lint refuses it there. Run it in CI beside rocx check (tooling).

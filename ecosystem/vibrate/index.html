The ecosystem · vibrate

A buzz from a handler

Vibrate.pattern!([300, 150, 300]) buzzes the phone twice: 300 ms on, 150 ms off, 300 ms on. The same line works in Chrome on Android and in an app on the Android host.

Use it when a phone should buzz: a timer ran out, a message arrived, a tap should be felt. Call Vibrate.once! or Vibrate.pattern! from a handler. The pomodoro example buzzes when a session ends.

Vibrate is a module both halves of an app compile, so a component that buzzes type-checks on the server and in the browser. Vibrator is a plugin that serves a small script every page loads, which passes the buzz to the browser. An Android app on the native host needs no script: the host runs the buzz itself.

Then import vibrate.Vibrate wherever you buzz.

Buzzing#

The whole module is two functions:

  • Vibrate.once!(400) buzzes once, for 400 milliseconds.
  • Vibrate.pattern!([200, 100, 200]) takes durations in milliseconds, alternating on and off, as navigator.vibrate takes them: buzz, rest, buzz.

A step longer than 10 seconds is cut to 10, and only the first 32 steps play.

A buzz is a Browser.call! underneath, with the same rules. It runs after the handler finishes and the page shows what it changed. Only a handler can buzz: an event's handler, an effect's apply, or a timer's callback. Calling it while the page computes (a hole, a memo or a component's body), or on the server, fails. In a browser#

The plugin serves its script at /rocx/plugins/vibrate/vibrate.js. Every page loads it before start.js, so it is ready before the page hydrates. It registers the browser effect vibrate.pattern on window.rocxEffects, which passes the pattern to navigator.vibrate:

Chrome on Android buzzes. Desktop browsers, Safari and Firefox give pages no motor, so there a buzz does nothing, and nothing fails. A browser may also stay still until the reader has touched the page; that isn't an error either.

On a phone#

On the native Android host, a plugin's Browser.call! goes to a native handler of the same name, with no script. The host has two: audio.play (for audio, a MediaPlayer that fetches the sound from the app's server) and vibrate.pattern, which plays the pattern on Android's Vibrator as a waveform. The app's manifest asks for android.permission.VIBRATE, which Android grants at install, so the user sees no prompt.

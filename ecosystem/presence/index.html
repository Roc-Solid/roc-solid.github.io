The ecosystem · packages/presence

Who is here, who is typing, and where they point

An avatar stack, a typing line and live cursors for a shared page, fed by a room the server keeps. Tabs come and go cleanly: a reload doesn't flicker, and a laptop that shuts is swept out.

Use it when people share a page (a board, a document, a quiz) and should see who else is there. A room is the set of people on that page right now, each with a name, a colour and a status. The package has three components that show a room (<AvatarStack>, <TypingIndicator> and <LiveCursors>), a browser side that joins one (Presence.join!), and a server side that keeps it (PresenceServer), all on a route's channel.

A room, in your browser#

This site has no server, so the demo plays its part: it keeps a list of who is here and tells the package's stores what a room's channel would. Press a button, or let Auto (on from the start) act every 1.5 seconds.

Using it#

Name the package in the app's header, as for any package. It isn't a plugin, so the program needs nothing more:

rocx build copies the components and browser stores into the app, so both halves compile them. Each component takes its data as an accessor (a function ending in ! that reads a value), so it shows whatever feeds it: a room's channel, or here, the demo.

In an app, a room is a route's channel, named by its URL. The channel's check admits a member as the person the middleware says they are: key and metadata come from the server, never the page. Its hooks are PresenceServer's, so a tab joins as it subscribes and leaves when the subscription ends. The whole route from examples/board:

The page joins with Presence.join!, given the channel. It subscribes, tells the room every 15 seconds that the tab is still here, and returns the accessors the components read (members!, others!, typing!, cursors!) and the functions that tell the room about this tab (status!, update!, typed!, moved!…). It all goes over the tab's one live stream, with its other channels; presence needs no endpoint.

A status is Online (the start), Away, Busy or Offline: a typo is a compile error, and the avatar stack knows how to show each. Set it from a handler or an effect with (here.status!)(Busy). To show a hidden tab as away, add <Document on:visibilitychange.visible={here.visible!} />: while hidden, the tab is Away and its cursor gone; shown again, its status comes back.

A member's metadata, Wire.Meta(d), is what the components show (name, picture, colour, status) plus data: the app's own, of any type JSON can carry and == can compare ({} for none). The channel's check sets it first; the page changes data with (here.update!)(data), up to a kibibyte of JSON. On the board it is the card a person has open ({ card : Str }), shown on each tile. Name, picture and colour stay the server's. A room where only the server may set data refuses Update in its own receive!. Wire.meta(name, data) makes metadata, leaving the rest to the components.

How a room works#

The server keeps the room in its own memory: no broker to run. Room is the room's state: who is here, with their metadata, since when, and from which tabs. join, leave, update (new metadata) and sweep return the changes others should hear (Joined, Left or Changed), numbering the state with each. Room never reads a clock: the caller passes the time in, so tests check a timeout without waiting:

  • Leaving has a grace period. A member with two tabs is one face, and leaves with the last. A tab whose stream ends leaves after five seconds unless it is back, so a reload or reconnect doesn't flicker out and in. A page that drops the room while the tab stays open (it went to another room) leaves at once: its on_close! hook is told Dropped.
  • Vanishing has a timeout. A page says it is here every 15 seconds; a tab unheard for 75 seconds (a laptop shut, a network gone) is swept out, however long its connection lingers. Browsers may slow a hidden tab's timers to once a minute, so 75 seconds is that minute plus a beat.
  • Changes are numbered. A page's copy of the room (Mirror) takes a snapshot, then each change in order, ignoring any older than the snapshot. A skipped number means a missed change, and the page asks for a fresh snapshot.
  • Kept in memory, swapped in. Each room lives in the server's Kv store. A change reads the room, sweeps it, changes it, and writes it back only if no one else changed it meanwhile (Kv.swap!), else reads it again. So two tabs joining at once both count, and nothing is written to the database. The change is then published on the room's channel, numbered. A room silent for a quarter of an hour is forgotten.
  • Typing and cursors are passed on, never kept. The server forwards them to the other tabs. Only a cursor's latest place counts, so a tab that falls behind skips to it.

The stores#

The browser's side is a set of Solid-style stores: functions you call in a component, like create_signal!, that keep state in signals. join! is a whole room on its channel; the others are its parts, and take what a room says however it arrives, so you can feed them from elsewhere, as the demo does.

StoreGives
Presence.join!(channel)the room on a route's channel, joined while the component is on the page: everything create_room! gives, fed by the channel, plus others! (everyone but you) and what this tab says: status!(status), update!(data), typed!() and done!(), moved!(point) and away!(), visible!(shown). Every 15 seconds it tells the room this tab is here, and repeats its data if the room has other data for it
Presence.create_room!(on_gap!)all the parts at once, fed a room's events with heard!(event): members!, synced!, me! (this tab's key and id), typing! (others' keys), cursors! (others'), and lost! for when the stream drops. Someone who leaves stops typing, and their cursor goes
Presence.create_presence!(on_gap!)who is here: members!, synced!, receive!(message), lost!. on_gap! runs when a change was missed
Presence.create_typing!(ttl)who is typing: who!, started!(key), stopped!(key). A ping lasts ttl milliseconds
Presence.create_typist!(every, send!)your own typing: call typed!() on each key and done!() when the text is sent or left. send! is given Started (at once, then at most every every milliseconds) or Stopped
Presence.create_cursors!({ idle, forget })others' cursors: shown!, moved!(move), gone!(key)
Presence.create_pointer!(every, send!)your own pointer: moved!(point) and away!(). send! is given Moved(point) at once, then at most every every milliseconds (the latest place held and sent when due, so a cursor ends where the pointer stopped), or Away

Call each store at most once per handler. As in Solid 2.0, a handler's writes apply when it is done, so a second call sees the store as it was before the first, and the first change is lost. A channel gives each event its own handler, so a page fed by one is safe. A store whose entries expire (typing, idle cursors) runs a quarter-second timer only while something can expire.

The demo, with no channel, does what one would: a press tells the stores what happened, one call each, and each cursor move comes from its own timeout.

The modules#

Under the components and stores is plain Roc on no platform, so the server's hooks and the browser's stores run the same code. The browser sees these modules through the package's browser.roc; the server also sees PresenceServer. roc test packages/presence/main.roc runs their expects. The package's README lists every function.

Styling#

Sizes and colours come from CSS custom properties. The avatar stack: --avatar-size (2rem), --avatar-overlap, --avatar-ring (the ring between faces; set it to the page's background), --avatar-font, --avatar-more, --avatar-away, --avatar-busy and --avatar-offline (an offline face's opacity, 0.5). The typing line: --typing-color and --typing-size. Cursors: --cursor-glide (0.12s; the demo's is 1.4s) and --cursor-font. Under prefers-reduced-motion, the dots stop bobbing and cursors jump instead of gliding.

Status#

Everything above works today. In examples/board, two people in their own browsers see each other, which card each has open, one going away while their tab is hidden, and a third leaving when they close their browser.

Not yet (the package's PROPOSALS.md has details): the live stream itself as the heartbeat (today the page sends one every 15 seconds), and a room named by the page's path with no route of its own (a "who's viewing this page" stack).
